## 📖 ภาพรวมระบบ (System Overview)

**IT VERTEX** คือระบบบริหารจัดการงานซ่อมคอมพิวเตอร์ โน้ตบุ๊ก ปริ้นเตอร์ และอุปกรณ์ไอที ออกแบบมาเพื่อเชื่อมโยงการทำงานระหว่าง **หน้าร้าน (Staff)**, **ช่างซ่อม (Technician)**, **ลูกค้า (Customer)** และ **ผู้จัดการ (Manager)** ให้ทำงานร่วมกันได้อย่างไร้รอยต่อ

### สถาปัตยกรรมระบบ (Architecture):
- **Frontend:** React Native (Expo SDK 54), Expo Router v6 (File-based Routing), NativeWind (Tailwind CSS)
- **Backend API:** Node.js (Express REST API), JWT Authentication, Bcryptjs, Multer
- **Database:** PostgreSQL (รองรับ Relational ER Diagram สมบูรณ์ พร้อมฟังก์ชัน Auto Seed Data)

## 👥 บทบาทผู้ใช้งานในระบบ (User Roles & Permissions)

| บทบาท (Role) | หน้าที่และความรับผิดชอบหลัก |
|---|---|
| **พนักงานหน้าร้าน (Staff)** | รับเครื่องซ่อมใหม่ (`/receive`), บันทึกข้อมูลลูกค้า, ออกใบรับซ่อม, ตรวจสอบการชำระเงิน (`/verify-payment`), ส่งมอบเครื่องพร้อมเซ็นชื่อรับเครื่อง (`/deliver-handover`) |
| **ช่างซ่อม (Technician)** | ตรวจเช็คสภาพเครื่อง, วินิจฉัยอาการเสียจริง, ออกใบเสนอราคาพร้อมเลือกอะไหล่/ค่าบริการ (`/make-quote`), ดำเนินการซ่อม, เปลี่ยนสถานะเป็นรอชำระเงินเมื่อซ่อมเสร็จ |
| **ลูกค้า (Customer)** | ติดตามสถานะงานซ่อมแบบ Real-time, ตรวจสอบใบเสนอราคา (กดอนุมัติ / ขอแก้ไข / ขอยกเลิก), ดูประวัติใบรับซ่อมและใบเสร็จ |
| **ผู้จัดการ (Manager)** | ดูแดชบอร์ดภาพรวม สถิติงานซ่อม รายได้ จัดการข้อมูลอะไหล่/บริการ และจัดการข้อมูลพนักงานในระบบ |

## 🚀 ขั้นตอนการติดตั้งและรันระบบ (Step-by-Step Installation)

### ขั้นตอนที่ 1: ตั้งค่าฐานข้อมูล PostgreSQL

1. เปิดโปรแกรม **pgAdmin 4** หรือใช้งานผ่าน Terminal / PowerShell ด้วย `psql`
2. สร้างฐานข้อมูลใหม่ชื่อ **`app_data`**:
   ```sql
   CREATE DATABASE app_data;
   ```
3. นำเข้า (Import) สคริปต์ฐานข้อมูลจากไฟล์ `back-end/database.sql`:
   - **วิธีที่ 1 (ผ่าน Terminal / Command Prompt):**
     ```bash
     # เข้าไปที่โฟลเดอร์ back-end
     cd back-end

     # รันคำสั่ง psql เพื่อ import ข้อมูล (ระบบจะถามรหัสผ่านของ postgres)
     psql -U postgres -d app_data -f database.sql
     ```
   - **วิธีที่ 2 (ผ่าน pgAdmin 4):**
     - เปิด pgAdmin 4 -> เชื่อมต่อ Database Server
     - คลิกขวาที่ฐานข้อมูล `app_data` -> เลือก **Query Tool**
     - เปิดไฟล์ `back-end/database.sql` คัดลอกคำสั่งทั้งหมดมาวาง
     - กดปุ่ม **Execute (F5)** เพื่อรันสคริปต์
4. *หมายเหตุ:* ในไฟล์ `database.sql` มีโครงสร้างตาราง ข้อมูล Master Data ครบถ้วน (ประเภทเครื่อง, ยี่ห้อ, รุ่น, อะไหล่, ค่าบริการ, สถานะงาน, บทบาท) พร้อมทั้ง **บัญชีผู้ใช้งานทดสอบ (Profiles) ทั้ง 4 บทบาท** ไว้ให้พร้อมใช้งานทันที โดย **ไม่มีข้อมูลงานซ่อมค้าง (Mock Data)** เพื่อให้ผู้ทดสอบสามารถจำลองกระบวนการทำงานจริงตั้งแต่เปิดงานซ่อมใหม่ได้ด้วยตนเองอย่างสมบูรณ์

---

### ขั้นตอนที่ 2: ติดตั้งและรัน Backend API

1. เปิด Terminal เข้าไปยังโฟลเดอร์ `back-end`:
   ```bash
   cd back-end
   ```
2. ติดตั้ง Dependencies:
   ```bash
   npm install
   ```
3. ตรวจสอบหรือสร้างไฟล์ `.env` ที่โฟลเดอร์ `back-end/.env`:
   ```env
   DB_USER=postgres
   DB_PASSWORD=******
   DB_HOST=localhost
   DB_PORT=******
   DB_NAME=******
   JWT_SECRET=*********
   PORT=3002
   ```
   *(แก้ไข `DB_PASSWORD` ให้ตรงกับรหัสผ่าน PostgreSQL บนเครื่องของคุณ)*

4. สตาร์ต Backend Server:
   ```bash
   # โหมด Development (Auto reload)
   npm run dev

   # หรือรันปกติ
   npm start
   ```
5. เมื่อรันสำเร็จ จะแสดงข้อความ:
   ```text
   ✅ Connected to PostgreSQL (app_data)
   🚀 IT VERTEX API Server running on port 3002
   📖 API Documentation available at http://localhost:3002/api-docs
   ```

---

### ขั้นตอนที่ 3: ติดตั้งและรัน Frontend (Expo App)

1. เปิด Terminal อีกหน้าต่างหนึ่ง แล้วเข้าไปยังโฟลเดอร์ `my-app-main`:
   ```bash
   cd my-app-main
   ```
2. ติดตั้ง Dependencies:
   ```bash
   npm install
   ```
3. *(ตัวเลือก)* ตั้งค่าไฟล์ `.env` ในโฟลเดอร์ `my-app-main/.env` (หากรันบน Web Browser ปกติ ระบบจะชี้ไปที่ `http://localhost:3002/api` ให้อัตโนมัติ):
   ```env
   EXPO_PUBLIC_API_URL=http://localhost:3002/api
   ```
   > 💡 **ข้อแนะนำกรณีทดสอบผ่านมือถือจริง (Expo Go):** ให้เปลี่ยน `localhost` เป็นหมายเลข IP เครื่องคอมพิวเตอร์ของคุณ เช่น `http://192.168.1.50:3002/api` เพื่อให้อุปกรณ์มือถือสามารถเชื่อมต่อ Backend บนเครื่องคอมพิวเตอร์ได้

4. สตาร์ต Expo Dev Server:
   ```bash
   # รันบน Web Browser (แนะนำสำหรับการทดสอบที่สะดวกรวดเร็ว)
   npm run web

   # หรือเปิด Expo Menu รวม
   npx expo start -c
   ```
5. เปิดเบราว์เซอร์เข้าใช้งานที่: **`http://localhost:8081`**

## 🎬 คู่มือการจำลอง Flow การทำงานตั้งแต่ต้นจนจบ (Simulation Guide)

คุณสามารถทดสอบวงจรการทำงานจริงของร้านซ่อมได้ตามลำดับดังนี้:

### 1️⃣ ขั้นตอนที่ 1: พนักงานรับเครื่องซ่อมหน้าร้าน (Staff)
1. ออกจากระบบ (หากล็อกอินอยู่) แล้วล็อกอินด้วยบัญชี **Staff** (`staff1@gmail.com`)
2. กดแท็บ **"รับเครื่อง"** (`/receive`) ด้านล่าง
3. ค้นหาลูกค้าเดิม (เช่น `ลูกค้า ใจดีที่สุด`) หรือกรอกข้อมูลลูกค้าใหม่
4. กรอกข้อมูลอุปกรณ์:
   - เลือก **ประเภทอุปกรณ์** (เช่น Notebook / PC)
   - เลือก **ยี่ห้อ (Brand)**: สามารถเลือกจากยี่ห้อที่มีอยู่ หรือพิมพ์ค้นหาและกด **`+ ใช้ระบุเอง`** หากเป็นยี่ห้อใหม่
   - เลือก **รุ่น (Model)**: สามารถเลือกจากลิสต์ หรือพิมพ์ระบุรุ่นเองได้
   - ระบุอาการเสียที่ลูกค้าแจ้ง (เช่น *เปิดเครื่องติดแต่ไม่ขึ้นภาพ*)
5. กดปุ่ม **"ตรวจสอบข้อมูลและออกใบรับเครื่อง"** -> ตรวจสอบตัวอย่างใบรับซ่อม -> กดยืนยัน
6. งานซ่อมใหม่จะถูกบันทึกเข้าสู่ระบบในสถานะ **`รอตรวจเช็ค`** (Job ID: เช่น `REP-xxxxxx`)

---

### 2️⃣ ขั้นตอนที่ 2: ช่างรับเครื่องไปตรวจเช็คและทำใบเสนอราคา (Technician)
1. สลับบัญชีเข้าสู่ระบบด้วย **Technician** (`technician1@gmail.com`)
2. ในหน้า **"รายการซ่อม"** จะพบงานซ่อมใหม่ที่เพิ่งรับเข้ามา
3. กดเข้าไปดูรายละเอียด -> เปลี่ยนสถานะเป็น **`ดำเนินการตรวจเช็ค`**
4. เมื่อตรวจเช็คเสร็จ กดปุ่ม **"ใบเสนอราคา"** เพื่อไปยังหน้าทำใบเสนอราคา (`/make-quote`)
5. ระบุ **อาการเสียจริงที่ตรวจพบ** (เช่น *แรมเสีย หรือ เมนบอร์ดช็อต*)
6. เลือกรายการ **อะไหล่** และ **ค่าบริการ** จากระบบ (ระบบจะคำนวณยอดรวมค่าซ่อมให้อัตโนมัติ)
7. กด **"บันทึกและส่งใบเสนอราคา"** -> ยืนยันการส่ง
8. ระบบจะส่งใบเสนอราคาให้ลูกค้าพิจารณาทันที และสถานะงานซ่อมจะเปลี่ยนเป็น **`รอการอนุมัติ`**

---

### 3️⃣ ขั้นตอนที่ 3: ลูกค้าตรวจสอบและอนุมัติใบเสนอราคา (Customer)
1. สลับบัญชีเข้าสู่ระบบด้วย **Customer** (`cus1@gmail.com`)
2. ลูกค้าจะเห็นรายการงานซ่อมที่อยู่ในสถานะ **`รอลูกค้าอนุมัติ`**
3. กดดูรายละเอียดใบเสนอราคา ลูกค้าสามารถเลือก:
   - **อนุมัติการซ่อม:** กดยืนยันอนุมัติ -> สถานะงานซ่อมเปลี่ยนเป็น **`อนุมัติแล้ว/รอซ่อม`**
   - **ขอแก้ไข:** ระบุหมายเหตุที่ต้องการให้ช่างแก้ไขราคาหรือรายการ
   - **ยกเลิกซ่อม:** หากไม่ต้องการซ่อม (คิดเฉพาะค่าตรวจเช็คมาตรฐาน 300 บาท)

---

### 4️⃣ ขั้นตอนที่ 4: ช่างดำเนินการซ่อม (Technician)
1. สลับกลับมาที่บัญชี **Technician**
2. เมื่อเห็นงานอยู่ในสถานะ **`อนุมัติแล้ว/รอซ่อม`** ช่างกดรับงานเพื่อทำการซ่อมจริง (สถานะ: `กำลังซ่อม`)
3. เมื่อซ่อมเสร็จเรียบร้อย ช่างกดเปลี่ยนสถานะเป็น **`รอชำระ`** เพื่อส่งต่อให้หน้าร้านเตรียมส่งมอบ

---

### 5️⃣ ขั้นตอนที่ 5: หน้าร้านตรวจสอบการชำระเงินและส่งมอบเครื่อง (Staff)
1. สลับบัญชีเข้าสู่ระบบด้วย **Staff**
2. ไปที่แท็บ **"ส่งมอบ"** (`/deliver`) หรือ **"รายการซ่อม"** จะพบงานที่อยู่ในหมวด **`รอชำระ`**
3. หากลูกค้าโอนเงิน: กดปุ่ม **"ตรวจชำระ"** เพื่อตรวจสอบสลิปและยืนยันการรับเงิน
4. เมื่อลูกค้ามารับเครื่อง: กดปุ่ม **"ส่งมอบ"** (`/deliver-handover`)
5. ตรวจสอบรายการและให้อนุญาตลูกค้า **เซ็นชื่อรับเครื่องแบบดิจิทัล (Digital Signature)** บนหน้าจอ
6. กดยืนยันส่งมอบ -> สถานะงานจะเปลี่ยนเป็น **`เสร็จสิ้น`** พร้อมพิมพ์ใบเสร็จรับเงินให้ลูกค้าได้ทันที

## 🛠️ การแก้ปัญหาที่พบบ่อย (Troubleshooting)

### 1. Backend เชื่อมต่อฐานข้อมูลไม่ได้ (Database Connection Error)
- **สาเหตุ:** ข้อมูลใน `back-end/.env` ไม่ตรงกับเครื่องของคุณ หรือ Service PostgreSQL ยังไม่ได้เปิด
- **วิธีแก้:**
  - ตรวจสอบว่า Service PostgreSQL บน Windows กำลังทำงานอยู่ (เปิด Task Manager -> Services -> ดู `postgresql-x64`)
  - ตรวจสอบ `DB_PASSWORD` และ `DB_PORT` ในไฟล์ `back-end/.env` ให้ถูกต้อง

### 2. Frontend ไม่สามารถดึงข้อมูลจาก Backend ได้ (Network Request Failed)
- **วิธีแก้:**
  - ตรวจสอบว่า Backend กำลังรันอยู่ที่พอร์ต `3002` และไม่มี Error
  - หากทดสอบบน **Web Browser:** ให้เข้าผ่าน `http://localhost:8081`
  - หากทดสอบบน **มือถือผ่าน Expo Go:** ไม่สามารถใช้ `localhost` ได้ ให้ระบุ Local IP Address ของคอมพิวเตอร์ใน `.env` เช่น `EXPO_PUBLIC_API_URL=http://192.168.1.XX:3002/api`

### 3. พอร์ต 3002 หรือ 8081 ถูกใช้งานอยู่ (Port Already in Use)
- **วิธีแก้:** สามารถปิดโปรเซสที่ค้างอยู่ หรือเปลี่ยนพอร์ตในไฟล์ `.env` ของ Backend เป็นพอร์ตอื่น เช่น `3003`
